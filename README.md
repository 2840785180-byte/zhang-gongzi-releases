# 监控更新发布页

这里只发布“监控”桌面 App 的可执行文件和版本说明，不包含用户配置、视频、日志、聊天记录或源码。

## 用户更新

打开 `监控` App，点击左侧底部的 `检查更新`。发现新版本后确认一次，App 会自动下载、校验并安装更新，随后重启 App。正在运行的监听器不会被停止。

## v1.4.8

- 除“一键识别 GPT 路径”外，监听器、启停脚本、默认指令、GPT 发送桥接和插件文件全部合并到“一键安装/修复全部”。
- 一键修复会逐项显示五项结果并执行 MCP 握手检测。
- 修复监听运行时更新监听器被文件占用的问题：只停止本安装目录对应的旧进程，原子替换并校验文件，随后自动恢复监听。
- 包内版本连续 3 轮隔离测试通过：五项补齐、插件握手、旧监听器热替换、两次启停和 GPT 路径识别。

## v1.4.7

- 修复部分 Windows 电脑中文路径乱码、监听只能启动不能停止或没有监听效果的问题。
- 修复整批视频共用一条文字并只发送一次；不同监听仍可分别使用自己的模板和目标聊天。
- 增加运行状态心跳、附件数量核对、插件副本自动修复和 App 内更新进度显示。

## v1.4.6

- 修复视频发送成功但正文可能变成 `·` 的问题。
- 桥接在写入正文后、添加附件后和发送前都会回读输入框；正文不一致时拒绝发送。
- 监听日志新增 `prompt_actual_chars`、`prompt_verified` 和 `prompt_method`，可核对实际收到的字数与校验结果。
- 连续 3 轮真实 ChatGPT 整批投递通过：每轮 4 个视频合并成一次发送，4 个附件和完整正文均收到。
- 连续 3 轮全新临时用户目录安装通过：窗口、双进程、插件注册、MCP 握手、监听器和桥接哈希全部正常。
- 隔离测试期间正式 Codex 配置未发生变化。

## v1.4.5

- 修复部分电脑重复打开 App 时出现 `can't invoke "destroy" command: application has been destroyed` 的崩溃。
- 改为 Windows 系统级单实例锁：重复打开只显示正常提示，不再创建或销毁未完成的窗口。
- 连续 3 轮全新目录安装、插件注册、重复启动和 MCP 校验全部通过。
- 连续 3 轮正式版桌面快捷方式启动通过；正在运行的监听器不会被重启。

## v1.4.4

- 新增主界面一键补齐发送桥接、监听器、默认指令和 Codex 插件注册。
- 修复全新电脑首次安装时空配置导致的 Codex 注册失败。
- 修复启动监听时 PowerShell 参数绑定错误，以及后台监听器占用输出管道导致的卡顿。
- 修复从空目录或旧工作目录启动时选错程序目录的问题。
- 修复一键插件安装后 MCP 测试遇到 UTF-8 BOM 的问题。

新版 `Monitor.exe` 已内置监听器运行文件和插件安装文件，不再要求电脑预先安装 Python。首次启动会在程序所在目录自动完成补齐；也可以点击“一键安装/修复全部”重新修复。

## 发布约定

- Release 标签使用 `v1.4.3` 格式。
- Release 附件文件名使用 `Monitor.exe`。GitHub 会把中文附件名清洗成 `default.exe`，因此下载文件使用稳定的英文名；App 显示名、安装名和快捷方式仍是“监控”。
- App 会校验 GitHub 提供的 SHA-256 和文件大小，校验失败时不会替换当前版本。

当前版本：`v1.4.8`
